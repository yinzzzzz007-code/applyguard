# ApplyGuard 测试计划与报告规则

制定日期：2026-10-29，北京时间（UTC+8）。范围：本地实验应用，重点为异常输入、事实保真和恢复能力。

## 参考依据与采用方式

以下是公司公开资料中的实践，不代表获得了其完整内部测试规范，也不宣称本项目通过其认证。

| 一手来源 | 本项目采用的做法 |
| --- | --- |
| [Google：Software Engineering at Google，第11章](https://abseil.io/resources/swe-book/html/ch11.html) | 优先快速、确定的单元测试；localhost 集成测试验证接口；少量端到端验证关键流程。区分执行资源与覆盖范围，不机械套用比例。 |
| [Google：Test Sizes](https://testing.googleblog.com/2010/12/test-sizes.html) | 测试彼此独立，明确是否使用文件、localhost 或外部模型；固定随机种子，避免依赖测试顺序。 |
| [CODING：覆盖率计算与门禁](https://ci.coding.net/docs/internal-steps/testing/coverage.html) | 保留机器可读报告；后续接入总量及增量覆盖率门禁。当前未安装覆盖率工具，也未配置远端 CI，不报告覆盖率百分比。 |
| [腾讯云：服务性能测试流程，更新于2025-01-03](https://cloud.tencent.com/document/product/653/83550) | 先定义业务链路和测试数据，再规定并发及持续时间，记录错误和配置快照。当前只做小规模并发正确性验证，不能称为容量压测。 |

## 分层执行

1. 每次修改先跑受影响模块，失败则定位为产品缺陷、测试预期错误或环境缺失。
2. 修复后跑相关回归；完成一组改动后跑完整后端回归。
3. 涉及前端逻辑时运行前端测试；涉及打包或界面时补构建及真实浏览器流程。
4. 模型事实准确性实验独立执行，不把模型桩、固定规则或随机错误类型计入真实模型评测成绩。
5. 开发副本和当前运行副本分别记录路径及源文件 SHA256，不能互相替代验收。

## 通用项目：本轮已执行

逐项结果及时间以 `output/test-reports/` 的独立报告为准。边界测试包含真实 PDF 与有明确标记的解析器桩。

| 项目 | 覆盖内容 | 通过标准 |
| --- | --- | --- |
| 输入契约 | 缺字段、错误类型、未知模式、根节点非对象、损坏 JSON、非法 UTF-8 | 参数错误 422；编码/JSON错误 400；返回统一错误体 |
| 文件输入 | 假 PDF、空文件、损坏、加密、空白页、无文本绘图页、文件名异常 | 明确提示，不能把部分读取误报完整成功 |
| 编码及边界 | 非法 Base64、5MiB边界、编码长度、20页、20,000字符 | 越界拒绝，不静默修复编码或截断正文 |
| 失败恢复 | 错误请求后继续合法请求；单页读取失败 | 服务继续可用，失败不返回残缺简历 |
| 隔离 | 固定种子120次错误类型输入、16个不同邮箱的请求/4线程 | 预期错误状态；各请求结果无串号；请求对象未被修改 |
| 外部依赖故障 | 模型桩返回空对象、无效类型、捏造内容、过多条目 | 保留规则抽取结果，不清空已识别字段 |
| 本地处理约束 | 离线模式、正文含指令、PDF含JavaScript | 离线不构造模型客户端；脚本仅作为文件数据读取 |
| 前端既有回归 | 当前应用 smoke 命令中的历史摘要、文案、材料及职位逻辑 | 各脚本断言通过；不等于浏览器界面验证 |

16个并发请求不是负载容量结论；120次随机类型输入也不是120种独立覆盖。未执行慢连接、解析压缩炸弹、长时间稳定性或真实模型提示注入评估。

真实模型新增实验本轮未执行。此前模型服务余额不足；本轮使用模型桩，不据此声称幻觉率、复核率或 SAG 优势有变化。用户真实简历仅用于 localhost 验证，不作为提交到仓库的测试夹具。

## 验收口径

- 本轮通用输入回归应全部通过，非法输入不出现未处理异常；任何跳过必须写原因。
- 重要字段丢失、捏造身份、跨人证据、旧核验状态直接恢复，均作为阻断发布的问题；专项尚未完成时不得宣称满足这些门槛。
- 模型专项先冻结独立测试集，按候选人/材料划分避免泄漏；建议至少200个正例和200个错误修改例，覆盖主要错误类型。双人独立标注并裁决分歧后才用于正式结论。
- 先测基线再定可行阈值。错误修改接受率 = 被自动采用的错误修改/全部被自动采用的修改；漏检率 = 被自动放过的错误修改/全部标注错误修改；误拦率 = 被错误拒绝的正确修改/全部标注正确修改；复核率 = 交人工的样本/全部样本。另报每类分母和置信区间。
- 复核率降低必须同时满足错误修改风险不增加；空输出、全阻断或跳过困难样本不能换取“高准确率”。

## 每次报告必须保留

运行后自动生成 `YYYYMMDD_HHMMSS_微秒_标签/`，含 `report.md`、`report.json`、`test.log`。失败、复测各一份，不覆盖旧报告。

必填：北京时间开始/结束、运行目录、测试范围、源文件指纹、环境、结果、耗时、失败/跳过原因及限制。测试方法数与参数子用例数分列；命令构建不冒充测试用例。敏感密钥和真实简历正文不得进入报告。

```powershell
$env:PYTHONUTF8='1'
.venv/Scripts/python.exe scripts/run_test_report.py --label abnormal tests.test_resume_abnormal tests.test_resume_sections
.venv/Scripts/python.exe scripts/run_test_report.py --label backend-full --all
.venv/Scripts/python.exe scripts/run_command_report.py --label frontend-smoke --cwd frontend -- powershell.exe -NoProfile -Command 'npm run smoke'
```

失败报告保留原始状态。修复说明引用新报告，不能把旧的 FAIL 改成 PASS。早期手工探测只能注明“补记、精确时间未记录”，不得补造测试耗时。报告入口是本地流程约定，尚未在远端 CI 强制执行。
