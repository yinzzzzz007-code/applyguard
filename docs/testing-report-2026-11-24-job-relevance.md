# 岗位推荐与经历匹配离线验收 · 2026-11-24

本文使用项目化名，保留实际统计结果。

## 实际操作

打开[离线复测工作区](http://127.0.0.1:8032/match)。在「证据匹配」点岗位原文中带颜色的职责或要求，查看项目名、经历原句、相关理由和材料原句。Nemotron 的训练经历会出现在框架要求下，可以确认实际框架、暂缓或更改。本人确认单独标识。经历最高匹配度达到 3.5/10 自动带入当前草稿，按分数降序显示。6/10 起标记为较强匹配。低于 3.5 分可以手动补选，移除的经历在同一岗位重新分析时保留移除状态。当前正文容量为 20 条。[岗位雷达](http://127.0.0.1:8032/jobs)使用本机 130 岗位快照。

## 草稿与材料入口的浏览器复测

在 8032 演示工作区用独立浏览器会话打开简历审查，8 条不同经历的显示分依次为 8.7、8、7.8、7.8、7.8、6.9、6.9、6.5。刷新后仍为 8 条。边界分值、手动移除与补回另由前端回归覆盖。公开仓库入口实查 octocat，匿名常规额度已耗尽时，公开搜索返回 8 个仓库。两个入口切换到私库时均显示授权按钮，自动私库授权请求为 0。

## 原始简历 × 字节 Seed Code Agent

固定同一份 PDF、同一段招聘原文和同一批岗位，三份指纹均与修改前一致。简历提取出 10 个项目。修改前进入匹配的岗位职责为 0 条，任职条件 5 项，共 2 个要求与经历的关联。修改后共有 14 项（含 4 条职责），37 个关联。一个项目可以支持多项要求，关联数不能当作通过核验的项目数。

| 预先选定的检查 | 结果 |
| --- | --- |
| Nemotron 对后训练、大模型或 RL、任选框架 | 前两项有直接经历。第三项保留训练原句，请用户确认实际框架 |
| Multi-Agent PPO 对 RL | 项目里的 PPO 可被召回 |
| DialogueBench 对工程场景的评测 | 标为可迁移的评测经历，软件工程场景待确认 |
| CacheBench 对问题分析和工程场景评测 | 分别找到直接经历和可迁移的评测经历 |

匹配读取标题、技术栈、整段经历及可用的同项目材料。术语和别名优先，语义相近可增加一条待核对的线索。只调用模型 API 不产生训练框架自述。

7 个应找回的关联均满足预期。5 个容易误判的对照通过。LedgerDemo 和 DialogueBench 未被当成深度学习框架经历，DialogueBench 在 Code Agent 专项上只列相关线索。另外两项出现在逐条复读时。Nemotron 的训练数据可关联到工程评测，但真实软件工程任务场景待确认。CacheBench 仅凭推理研究也不能直接满足“主导过有影响力的项目”，卡片具体列出主导作用和实际影响待确认。另用构造样本检查仅调用模型 API、明确 JAX 训练、材料机器学习与传统材料岗位。框架自述不会提高严格核验状态。
