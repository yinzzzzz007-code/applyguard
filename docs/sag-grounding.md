# SAG 与原子事实核验集成

本地实现基于 ApplyGuard 上游提交 `43416faf6b575b9f4d1afc9ae834e87e89a2cb61`，提交时间为北京时间 **2026-10-22 20:15:03**。2026-10-29 下载时通过 GitHub API 核对为默认分支最新提交。该报告原记录 10.29 本地实验；10.30 由姜凌天（Gitvextor）整理为分支发布，见 [发布说明](release-2026-10-30-gitvextor.md)。

## 已接入的流程

1. 上传原件、核对解析内容、关联到项目或经历。
2. 简历审查页选择 **SAG＋原子事实核验**。先检索原文再生成润色建议。
3. 对建议再次检索支持、反驳、更正材料。检索范围是当前候选人、当前经历中有效的原件；不拿其他项目的技能来支持本句。
4. 拆分技术、职责、数字、单位、时间、范围和否定等原子事实，再核查这些事实与整句覆盖情况。
5. 展示逐字引文、原件字符位置、可用时的页／行位置、文件版本及指纹。全部支持才标为 VERIFIED；矛盾为 BLOCKED，缺证据／失败为 NEEDS_REVIEW。
6. 人工核对后导出。导出接口重新读取原件并重新核验，人工确认不能覆盖未通过状态。

`SAG检索与润色预览` 供对照实验使用，始终保留待核验状态。单靠检索不会标为事实通过。

润色先形成建议，不直接覆盖编辑器。V2 同时检查建议事实与原稿有效信息的保留情况；建议不通过就保留原文，并独立重新核验原文。原文有错时仍会被阻断，恢复操作不会使其变成已通过。界面显示被拒建议、可能丢失的有效细节及敏感变化，用户再决定是否采用本次结果。

采用前后各保存一版到本浏览器，最多20版。历史同时保存当时状态、移出陈述和未采用建议，支持手动保存、回滚、通过回滚前自动备份撤销回滚；状态变化但文字未变也会留版。历史状态只是记录，不是“已通过”凭据，恢复后必须重新核验。它不是跨设备备份，也不是完整多人版本管理。

## 实际复用了什么

- 实际调用 PyPI **zleap-sag 0.15.0** 的 DataEngine：导入、事件／实体抽取、SQLite/LanceDB 索引和 full_expand 两跳检索。没有用关键词模拟 SAG。
- 原子事实核验借鉴 [FActScore](https://github.com/shmsw25/FActScore) 的分解与支持度思想，知识源换成职业原件；用独立的拆分、判定调用，并检查整句覆盖。
- 引文支持检查借鉴 [ALCE](https://github.com/princeton-nlp/ALCE) 的评测方向；本实现额外校验逐字子串、经历归属与版本。
- 后两项是本项目适配实现，**没有运行其官方完整基准，也不把结果叫作官方 FActScore／ALCE 分数**。拆分器和判定器默认是同一模型，仍可能出现相关错误。

SAG 原理与引擎接口见 [官方中文说明](https://github.com/Zleap-AI/SAG/blob/main/README-CN.md)。SAG 应用的 MIT 声明保留于 `third_party_licenses/SAG-MIT.txt`；安装的引擎包自身许可随包保留。没有更改 ApplyGuard 原始版权声明。

## 本机启动

Python 3.12 与 Node 22+。在项目根目录运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-sag.txt
cd frontend
npm ci
npm run build
cd ..
$env:PYTHONUTF8='1'
.\.venv\Scripts\python.exe scripts/run_grounded.py
```

启动脚本隐藏输入密钥，只留在进程内存；V2 默认 ChatAnywhere HTTPS 接口、gpt-4.1-mini、text-embedding-3-small。已有环境变量可覆盖模型选择。旧开发集表明 gpt-4o-mini 即使用严格结构仍可能误判主体、更正，不能只凭格式通过推断准确。打开 http://127.0.0.1:8000 。密钥不写进浏览器、Git 或结果文件。

应用和索引在本机，**模型请求会把检索上下文发给所配置的服务**。这不等于完全离线推理。实际试验只使用虚构材料。若已有 `APPLYGUARD_AI_API_KEY` 环境变量则直接使用。

主要配置参见 `.env.example`。`APPLYGUARD_GROUNDING_MODE=sag_atomic` 是服务端最低要求，客户端不能把它降成 sag/off。基础应用默认 off 以保留上游离线演示；上述启动脚本默认开启 atomic。服务仅支持本机单用户场景，经历归属检查不等于多租户权限认证。

如果本机防护软件设置了不可访问的 `SSLKEYLOGFILE` 而导致 Python SSL 初始化失败，可在启动的这一个终端执行 `Remove-Item Env:SSLKEYLOGFILE -ErrorAction SilentlyContinue`；不要关闭证书校验。首次建立索引与多路检索可能需要数分钟。直接访问后端提供的构建页面，可避免开发代理180秒超时。

## 接口与边界

- `POST /api/v1/resume/polish`：与 reverify 相同的 candidate_id、jd_text、resume_draft、claims，增加 grounding_mode。
- `POST /api/v1/workflow/reverify`：支持 sag/sag_atomic，服务端重建陈述编号与证据引用。
- `POST /api/v1/resume/export`：human_confirmed 必须为 true，服务端强制 atomic 并返回当前核验正文。不会投递招聘网站。

来源快照包括原文、文件版本、核对状态与关联；请求完成前再次比对，变化即失效。恢复历史、修改文字也使前端旧结论失效。导出进行新核验。无原件、已撤销链接、来源冲突、未知陈述编号、模型截断、缺原子事实、错误引文都不能沿用旧 VERIFIED。

页／行来自原件解析；字符偏移是拼接后解析文本的 Python Unicode 码点，0起始、右端不含，并非 PDF 像素坐标。种子经历库只有示例文本，不能冒充用户真实原件。人工确认只是使用决策，不是独立事实证明。

## 验证标准

V2 的固定样本、模型、代码指纹见 `output/expanded-eval/protocol.json`。`scripts/prepare_expanded_eval.py --freeze` 下载并冻结样本；`scripts/expanded_grounding_eval.py` 执行真实调用，`scripts/summarize_expanded_eval.py` 汇总，原始公共数据及模型引用保留在忽略目录 `data/local/expanded-eval/`。该脚本默认使用约数百次调用，需事先确认服务余额和额度；结果逐组保存，相同协议可续跑。不要把 FActScore/ALCE 思路适配的结果称为其官方评分。

速度优化保留三路检索：查询并发默认2，原子核验每批3句、并发2；缓存只存检索到的原件编号，目录绑定候选人、完整来源快照、模型配置，键绑定策略、查询与允许来源。每次读取重新使用当前原件内容。不能缓存旧 VERIFIED 来跳过导出前检查。严格结构由服务端生成陈述及原子编号；覆盖缺失最多修补一次，仍不完整则不通过。数字字面覆盖检查仅是保守补充，不能代替语义核验。

机制测试使用可控假模型检查入口和拦截，不用于证明语言模型准确率。执行：

```powershell
$env:PYTHONUTF8='1'
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
cd frontend
npm run build
npm run smoke
npm run lint
```

真实接口试验：`.\.venv\Scripts\python.exe scripts/live_grounding_pilot.py`；完成后运行 `scripts/verify_polished_pilot.py` 对该批润色文字再次原子核验。结果写入 `output/integration-live.json`，试验索引和原件在 `data/local/integration-pilot/`。不应提交这些运行时目录。小样本为作者设计的虚构案例，不是独立标注测试，也不能证明零幻觉。

正式效果验收建议另建冻结测试集，训练／调试与测试按候选人及项目隔离。两人独立标注原子事实，第三人裁决；保留全部分歧。至少覆盖新增技能、职责夸大、数值／分母、否定、更正、计划冒充完成、跨项目错配、无支持材料。对相同模型、材料、生成提示分别比较原实现、SAG、SAG＋原子核验，生成质量由独立人工判定。

必须同时报告计数、分母、置信区间及分类型结果：

- 漏检率 = 无依据／矛盾陈述被 VERIFIED 的数量 ÷ 所有无依据／矛盾陈述。
- 严格误拦率 = 有依据陈述被 BLOCKED 的数量 ÷ 所有有依据陈述。
- 正确陈述未自动通过率 = 有依据陈述被 BLOCKED 或 NEEDS_REVIEW 的数量 ÷ 所有有依据陈述。
- 复核率 = NEEDS_REVIEW 数量 ÷ 全部陈述；另报处理失败率，不把失败隐藏为正常复核。
- 引文精确度、原子事实漏拆率、更正材料召回率、版本定位正确率，以及每条延迟／费用／人工复核时间。
- 错改率 = 原本正确、改写后出现无依据事实的数量 ÷ 正确原稿数；支持细节丢失另计，不可只报改后句子为真。
- 纠错率 = 原本错误、改写后全部有依据的数量 ÷ 错误原稿数；同时报告修复后能否通过导出门槛。
- 净收益同时看新增错误、已修复错误和丢失信息；原文保持不变不算纠错。统计未采用的建议与最终可导出正文，避免把阻断状态当成已修复。

推荐发布前门槛（是建议，不是已达到的结果）：机制测试必须全部通过；独立集至少300条负例，若零漏放，其单侧95%漏检上界才约为1%；至少300条正例，严格误拦目标≤5%、正确陈述未通过率≤15%；所有模型失败和材料失效必须阻止导出。临界值应按实际风险和人工预算预先注册，不能看结果后修改。不能以“全部拒绝”冒充防幻觉成功。

## 后续改进

优先完成双人盲标和第三人裁决，检查模型共同偏差；以候选人/项目隔离数据，避免把同一项目十个句子当十份独立证据。其次增加显式主体归属、更正／撤回关系及单位运算约束；这些约束应先在开发集设计，再在新的保留集验证。提速下一步应独立评测轻量实体抽取、复用问题实体和更小的批处理输出，不能直接取消反驳、更正查询。

APP 后续采用后端不可变版本事件：每次 edit/suggest/accept/reject/restore 保存父版本、正文、作者、来源快照、模型/提示版本及修改原因；恢复旧文创建新版本，重新核验。逐项意见支持撤回拒绝和重新采用，保存前校验父版本防止并发覆盖；源文件撤销后所有依赖结果失效。验收包括刷新/重启后恢复、误删撤回、并发冲突和撤销材料后的导出阻断。当前浏览器20版只覆盖单机文字恢复。

建议预注册产品门槛：独立集复核率≤15%、正确原稿错改率≤1%、有效细节丢失≤2%、正确句未通过≤10%，同时漏放率的95%上界≤1%；每次与旧版比较必须同时满足，不能单独追求低复核。至少覆盖100个互不重叠项目并增加独立负例数量，置信区间按项目聚类。速度目标为已有索引的5句核验中位数≤30秒、p95≤60秒，首次建索引单列；在固定模型、硬件和并发下重复至少30组。以上均为待验收目标，不是本次已达到的保证。
