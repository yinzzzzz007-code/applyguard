## 目标与准备

检验用户能否独立完成「经历库 → JD → 证据匹配 → 陈述审查 → 模拟网申确认」，并正确理解证据来源、风险说明和 BLOCK。招募约 5–8 位有近期求职经历的同学进行形成性测试；这是发现问题的样本，不用来估计总体比例。每人使用项目内的虚构经历与 JD，不要求登录真实招聘网站，也不收集真实简历或账号。

开始前说明研究用途、预计 15–20 分钟、可随时退出；征得参与者同意后记录匿名笔记。默认不录屏、不拍照；如要拍摄，按 `docs/user-study/photo-consent-zh.md` 单独征求同意。用 P01、P02 等编号，不把姓名、联系方式或原始材料提交 Git。

## 主持词与任务

主持词：请按你自己的理解操作，边做边说你在找什么；我只会在你无法继续时给提示。页面里的经历和岗位都是演示数据，不会真实投递。

| 任务 | 给参与者的指令 | 独立完成标准 |
| --- | --- | --- |
| T1 经历库 | 找到一条与 Python API 相关的经历，指出支持它的证据 | 找到陈述及至少一个证据来源 |
| T2 JD 与匹配 | 输入示例 JD，运行离线工作流，说明哪项要求匹配最强 | 成功得到结果，并能指出要求与对应经历 |
| T3 简历与核验 | 查看已选与未选陈述，说明保留理由；找到一条陈述的核验状态 | 能区分「被选中」与「已核验」 |
| T4 模拟网申 | 查看拟填字段和未映射字段，完成所需人工确认 | 不把工作许可等字段当成系统推断的事实 |
| T5 阻断场景 | 切换预录阻断场景，解释为什么不能确认或复制填写稿 | 能指出不受支持片段，拒绝阻断陈述，并说明整单不能投递 |

任务顺序固定。主持人只在参与者停滞 60 秒或明确求助时给一次标准提示，并记录提示与时间；不提前解释风险颜色。最后请参与者在申请历史中找到本地模拟结果，并问其是否理解“未真实投递”。

## 记录口径

- 完成率：每个任务按「独立完成 / 提示后完成 / 未完成」记录。报告时分别给出人数，不把提示后完成算作独立完成。
- 完成时间：从读完任务开始，到满足标准为止；提示或失败也记录截止时间。
- 错误：误把阻断陈述当可用、尝试复制阻断值、误认为已投递、选错证据或漏看风险。记录具体动作，不仅记总数。
- 纠正：参与者主动发现错误并改正的次数；与主持人提示分开。
- 理解检查：分别请参与者解释 BLOCK、风险说明、证据来源、`RULE_FALLBACK` 和“模拟确认”。按「正确 / 部分正确 / 错误」编码，保留其原话的匿名摘录。

## 结束问卷（自编简化量表，不称 SUS）

对以下每项选 1–5 分：1 完全不同意，5 完全同意。

1. 我能看出每一步接下来要做什么。
2. 我能理解系统为什么选入或排除一条陈述。
3. 我能找到风险提示和它对应的证据。
4. 遇到 BLOCK 时，我知道怎样修改或停止。
5. 我能区分模拟确认与真实求职投递。

再问两个开放问题：哪一步最难？你希望改变什么？逐项报告分布和匿名例子；不把这份自编量表写成经过验证的 SUS 分数。
