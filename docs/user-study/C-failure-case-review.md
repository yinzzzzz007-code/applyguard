# C 对形成性研究材料的技术审阅

审阅对象：`survey-release-zh.md` 的 Q5–Q10、开放题；`interview-guide-zh.md` 的问题 3–7。此文是 C 的材料反馈，不是参与者结果；不修改 B 已冻结问卷。

问卷能定位证据难找、AI 夸大、ATS 不一致和确认偏好；访谈先问实际流程再展示概念，保留“没有发生”的反例，适合收集 Failure Cases。现有问卷不能单独确定某次错误的输入、主张、来源状态和后果，因此建议 B 在已有访谈追问中记录这些信息，去标识化后交接给 C。

| 待记录维度 | 中性追问或记录方式 | 转换成测试 |
| --- | --- | --- |
| 原文与改写差别 | “哪里变了？你怎样发现的？” | 角色升格、范围扩大、技能虚构 |
| 指标依据 | “这个数字当时怎么计算？谁完成的？” | 分母、百分比/百分点、团队归属 |
| 工作状态 | “当时已完成到哪一步？” | 计划冒充交付 |
| 证据可访问性 | “是没有材料，还是有但暂时不能提供？” | 无引用 BLOCKED；已有未核实来源 NEEDS_REVIEW，不能把不公开判成虚假 |
| ATS 决策 | “你为什么停下或改答案？后果是什么？” | 敏感字段、含义歧义、前后不一致 |
| 纠正与预期 | “当时如何解决？希望系统展示什么？” | 解释、来源预览、编辑后重新核验 |

不要收集真实简历、账号、敏感身份值或私有证据链接。B 可提供匿名事件编号、概述、经同意的匿名引语以及“实际发生/设想/不确定”标签；A 确认需求后，C 将其转成虚构化最小复现和预期状态，记录需求与测试对应关系。目前未收到真实访谈结果，不填写发现数量或用户偏好比例。
