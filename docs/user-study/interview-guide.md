# ApplyGuard formative study: semi-structured interview guide

> Extended English planning draft, not the fieldwork instrument. Use the [10–15 minute Chinese release guide](interview-guide-zh.md) for the Proposal study; do not combine question numbers or session durations.

## Session plan

Target: 4–6 eligible participants. Duration: 30–45 minutes. Use anonymous ID `Pxx`. A participant may optionally walk through a de-identified past resume version and JD on their own screen; the team does not collect, retain, or request the files. Use fictional materials if this is not comfortable. Never request an ATS account, phone number, employer name, or login.

1. Reconfirm consent, voluntary participation, and anonymous-quotation preference.
2. Reconstruct one recent application workflow from JD to resume. Start with actions and tools before discussing ApplyGuard.
3. Explore tool use, evidence organization, resume tailoring effort, and ATS friction.
4. Discuss a fictional ApplyGuard scenario and confirmation preferences.
5. Ask for failure cases and open feedback. Confirm any quotations selected for notes are anonymous.

## Core questions

1. Think of a recent application. From seeing the JD onward, walk me through each action, tool, comparison, pause, and rework step.
2. Where do you keep project, research, competition, or internship evidence? What makes retrieval difficult?
3. Which parts of tailoring take the most time or feel most repetitive?
4. When an AI tool proposes a stronger statement, how do you decide whether it is accurate enough to use?
5. What information do you fear an AI tool may invent, exaggerate, omit, or duplicate?
6. What makes ATS forms difficult after you have finalized a resume?
7. In this fictional scenario, a JD requests a skill absent from the evidence vault. What should the system do?
8. Which actions should be automatic, preview-only, blocked, or require explicit confirmation?
9. Does claim-to-evidence traceability help you? What explanation would you need to trust a selection?
10. What critical failure would make you stop using such a tool?
11. What should ApplyGuard deliberately avoid doing?
12. Is there anything else the team should know?

## Optional artifact walkthrough

If the participant volunteers a de-identified past resume/JD pair, ask why experiences moved, disappeared, or changed wording; whether a tool made the change; how evidence was checked; and whether later rework occurred. Do not record file contents or take screenshots. If no artifact is available, use the fictional scenario below.

## Optional probe: fictional scenario

Show only this fictional case: a candidate has verified PyTorch and LoRA evidence, but no verified distributed-training evidence. A JD prefers distributed training. Ask how the tool should display the gap and whether it may draft, flag, or block a related claim.

## Note-taking rules

- Record observations as `Pxx`, never as a name.
- Mark direct words only when anonymous quotation is allowed; otherwise paraphrase.
- Mark missing, ambiguous, or skipped responses instead of filling them in.
