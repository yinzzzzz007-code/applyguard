# ApplyGuard 形成性访谈提纲（10–15 分钟）

版本：`FS-2026-10-02-v1` · 目标：4–6 位符合筛选条件的参与者 · 记录编号：`P01`、`P02`……

## 开场（约 1 分钟）

核对筛选条件与研究同意；说明可以跳过问题或随时结束。询问是否允许匿名短句引用。**拍照是另一项独立选择**，拒绝拍照不影响访谈。只记去标识化文字笔记，不录音录像；参与者不上传简历、JD 或账号。

## 先还原一次真实流程（约 6–8 分钟）

1. 最近一次你为了某个岗位改简历是什么时候？从看到 JD 开始，一步一步讲你实际做了什么、用了哪些工具、哪里停顿或返工。
2. 你怎么判断 JD 最看重什么？怎么决定哪个项目放前面、哪个删掉？
3. 你要写技能或数字时，怎样确认它真有依据？曾经找不到依据或发现 AI 写错吗？如没有，也照实记录。
4. 把定稿内容填入 ATS 时，是否出现重填、答案不一致或敏感问题？

追问只问真实发生的例子；不提示参与者“应该担心 AI 虚构”。参与者愿意时，可在**自己屏幕上**展示脱敏的旧简历/JD，研究者只观察改动逻辑，不截图、不复制文件；也可使用虚构示例代替。

## 最后展示概念（约 3–5 分钟）

用虚构流程卡说明既定九模块：`Career Vault → JD Parser → Evidence Matcher → Resume Selector → Claim Validator → ATS Form Mapper → Risk Check → Human Confirmation → Audit Record`。说明这只是拟议流程，当前没有可供参与者完成任务的完整产品；系统不会自动提交申请。

5. 如果系统说“这句缺少证据”，你需要看到什么解释才会相信或纠正它？
6. 如果系统自动调整项目顺序或准备填写 ATS，哪些步骤必须先问你？
7. 这张流程卡里最不合理的一步是什么？最严重的失败会是什么？
8. 还有什么我们没问到？

## 记录规则

按时间顺序记录 Current Workflow，再记录具体 Failure Case、参与者原话/概述、反例与不确定处。原话仅在匿名引用获准时保留。访谈结束后立即去除可识别细节，填写 `response-template.md`；线下过程照片另按 `photo-consent-zh.md` 处理。
