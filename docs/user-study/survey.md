# ApplyGuard formative study: lightweight survey

> Archived English planning draft. Do **not** distribute this alongside the frozen Chinese form: [survey-release-zh.md](survey-release-zh.md). Question numbers below do not match the released instrument.

## Use

This is a mostly closed-choice survey for 10–20 eligible participants. It reconstructs the **current workflow first**; the ApplyGuard concept probe appears only at the end to reduce leading questions. It supports requirements discovery, not product evaluation.

Do not provide a name, contact information, employer name, real resume, ATS login, or other identifying information. You may skip any question or stop at any time.

Consent: `I meet the eligibility conditions, understand the privacy notice, and agree that anonymized responses may be analyzed for this course project.`  Yes / No

## A. Eligibility and context

1. Current study stage: senior undergraduate / postgraduate / neither.
2. Target role family. Select all that apply: software / AI or ML / data / other technical role.
2a. Are you currently concentrating your applications on the software, AI/ML, or data roles selected above? yes / no.
3. During the current search period, how many roles do you review or apply to per week? fewer than 5 / 5–7 / 8–12 / 13+.
4. How many substantial project, research, competition, or internship experiences could you reuse? fewer than 3 / 3–4 / 5–6 / 7+.

Only `senior undergraduate` or `postgraduate`, at least one of `software` / `AI or ML` / `data`, `yes` to 2a, `5+`, and `3+` responses qualify for the main sample.

## B. Current workflow: choose the statements that apply

5. After seeing a JD, which actions do you usually take? Select all that apply.

- Copy keywords into a document or notes.
- Compare the JD with a master resume.
- Reorder projects or experiences.
- Rewrite bullet points manually.
- Ask an AI tool to rewrite or summarize.
- Ask another person to check the content.
- Save a separate resume version.
- Fill ATS fields from the finished resume.
- Other / none of these.

6. How often do you create or substantially modify a resume for a role? every role / most roles / some roles / rarely.
7. Roughly how long does one tailoring session take? under 15 minutes / 15–30 / 31–60 / over 60.
8. Which tools do you currently use? Select all that apply: document editor / spreadsheet or notes / cloud drive or Notion / AI assistant / resume builder / job board or ATS / versioned files or folders / other.
9. Where do you usually keep evidence for an experience or achievement? Select all that apply: repository / report or document / certificate / chat or email / notes / nowhere organized / other.
10. Which workaround statements are true for you? Select all that apply.

- I maintain a master resume and copy it for each role.
- I use inconsistent or hard-to-track resume filenames.
- I compare several windows or documents manually.
- I rely on memory to decide whether a claim is accurate.
- I ask someone else to check whether content is overstated.
- I have no stable workaround.

## C. Incidents and control preferences

11. In the past application cycle, which problems have occurred? Select all that apply: emphasized an irrelevant experience / could not find proof for a metric or claim / AI wording was inaccurate or too strong / repeated similar content / used the wrong resume version / resume and ATS answers differed / did not know how to answer an ATS field / none of these / other.
12. Which actions should require explicit user confirmation? Select all that apply: changing a claim / removing an experience / filling an ordinary ATS field / filling a sensitive ATS field / using a new resume version / final submission.
13. Choose one preferred default for non-sensitive, evidence-backed content: fill automatically / show preview first / always ask first / do not fill automatically.
14. Choose one preferred default when a relevant JD requirement lacks stored evidence: show the gap only / draft but require review / ask for new evidence / block the claim entirely.

## D. Concept probe: answer after A–C

The proposed workflow links each resume claim to stored evidence, explains experience selection, flags missing support, and stops before risky actions.

15. If only two capabilities could remain, select up to two: evidence links / selection explanations / missing-evidence warnings / claim blocking / ATS draft assistance / resume-version tracking.
16. Which capability would you remove first? evidence links / selection explanations / missing-evidence warnings / claim blocking / ATS draft assistance / resume-version tracking / none.
17. In what situation would you stop using this kind of system? Select all that apply: it changes wording without permission / it hides source evidence / it creates inaccurate claims / it fills sensitive fields automatically / it is slower than my current method / it gives too many interruptions / other.
18. Is anonymous quotation permitted? no quotation / anonymous short quotation allowed.
19. Optional, one sentence only: name a critical failure case or an unlisted concern. Do not include identifying details.

## Facilitator checks

- Use the screener, not assumptions, to determine eligibility.
- Replace accidental identifying text with `[redacted]` before analysis.
- Record only the anonymous study ID in the response template.
- Treat closed-choice totals as descriptive formative evidence, not representative statistics or product-performance results.
