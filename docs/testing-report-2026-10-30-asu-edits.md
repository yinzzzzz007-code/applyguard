# ASu接入前后错改对照与限定语修复

日期：2026-10-30，北京时间。结论：已修复发现的限定语遗漏、等价改写误拦和引用标点误拦；目前没有证据证明接入ASu本身稳定降低错改。60条三组对照因ChatAnywhere余额不足中断，不能写成60条已完成。本轮仅更新本地实验版，未推送GitHub。

## 实际修复

| 问题 | 处理 | 边界 |
| --- | --- | --- |
| 模型批准删掉“尚未实施、仅离线、只负责、未训练”等限定语 | 润色前提供已核验事实的限定语清单；润色后独立检查，错误建议恢复原文 | 原文不正确时只保护其被支持的部分；规则不是完整语义理解 |
| 保留准确率80%→84%，却因省略重复的4个百分点被拒绝 | 同一指标、同一明确起止值、正确方向/单位可做Decimal精确等价检查；原子覆盖检查也接受该冗余差值 | 不放行4%相对增幅、不同指标、改动端点、不同时间/范围等情况 |
| estimated→estimating、did not train→without training被误当成删除限定语 | 补充词形和明确同义表达；只消解纯限定语误报，不覆盖含其他事实的复杂缺失 | 保留语义不确定项供复核 |
| 引用中中文句号/逗号被写为英文标点 | 唯一标点对应后回取实际原文片段，保留原始位置与版本 | 不拼接省略号、不改变否定、数字或单位；最终引用必须是原文连续子串 |
| “测得提升”改成“促成提升”可能被错误批准 | 对观察/评测工作新增因果或个人贡献措辞单独要求证据 | 不因数字等价而绕过归属保护 |
| 自动评分把分号变逗号算成事实错误，并漏掉职责范围删除 | 已逐条复核所有57条真实生成输出，保留原自动分数及修订理由，绑定输出SHA256 | 复核者为Codex，不冒充独立人工标注 |

上游ASu的6个原文件保持不变。新增实现位于`backend/services/edit_invariants.py`、`edit_guard.py`、`structured_verifier.py`等本地适配层。Agent授权/撤权、人工采用、历史版本回滚仍受原有流程控制；本次未自动连接用户Agent或读取额外目录。

- 固定原件用于隔离写作变化，不运行SAG检索或Harness。本报告不能被描述成新的SAG检索成绩。
- 已生成57条建议：接入前21条、ASu原版18条、ASu首轮修复18条；15条经历有完整三组生成结果。完整生成+核验+两种保留检查+自动盲审的配对只有9条。

## 待余额恢复后的验证标准

1. 在冻结副本中补齐60条既定三组对照，复用成功阶段；保持原模型、原件、种子和原代码，不将新修复偷偷混入旧组。
2. 对最终修复版另建报告，在冻结数据的未见部分及新增非模板真人授权材料上验证；已用于修复的失败样本只能算回归。
3. 逐项报告原始错改/全部样本、错改漏放/错误建议、安全改写误拦/安全改写、拒绝建议/发生改写、最终待复核/全部样本和端到端耗时；错误、超时、余额中断单列，分母不得混用。
4. 只在完整配对样本足够、盲评与独立人工复核一致，并且减少误拦没有增加错改漏放时，再认定版本改善。当前不作“零幻觉”或“ASu已经提升准确率”结论。
