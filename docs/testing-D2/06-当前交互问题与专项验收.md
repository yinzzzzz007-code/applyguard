# 当前交互问题与专项验收

## 1 总体判断

当前 D-2 的主要交互问题是**操作、状态提示与实际数据结果不一致**。表单可改，但匹配仍看旧种子；页面说保存成功，但可能没有保存；新 JD 下仍能看到旧结果；待复核手动陈述可被人工直接放行。这些应优先于圆角、配色调整。

本章基于 `816a246` 的真实 Chrome 浏览器检查与代码，区分“已复现”“待验证”“体验建议”。包含后来补测的刷新、重载、当前场景重复点击和表单标签关联，不是泛用 UI 清单。

## 3 补充问题的复现证据

这些为已有 18 条问题之外的补充项；事实和风险解释分开。

**D2-19 P2 未保存刷新无提醒导致丢改动。** 保存“交互甲已保存（虚构）”→ 改“交互乙未保存（虚构）”不保存→刷新。结果恢复甲，没有浏览器离开对话框。依据 interaction-run-01/I02；DemoContext 为内存状态，CareerVaultPage 仅在显式保存写session。此结论仅覆盖同标签刷新路径；关窗/路由变化按 IX-01 扩展。

**D2-20 P2 重载后的保存状态不清楚。** 保存甲→点从种子重载并确认→显示林晓舟，提示没有dirty标识→刷新又显示甲。依据 I03，CareerVaultPage resetFromSeed 仅重建表单、formModel 初始dirty=false，未改已存session。重载可以选择不自动落盘，但必须让用户知道尚未保存。

**D2-21 P2 当前场景重复点击重置输入。** 输入新的数据分析JD→点已经选中的正常·在线→再进岗位页。内容变回默认后端JD，无确认弹窗。依据 I04；AppShell.tsx 场景按钮无相同值保护，DemoContext.setScenario 总是重置JD/workflow。测试不要求禁止切场景，只要求不会无声丢失输入。

**D2-22 P2 表单标签关联缺失。** 本轮DOM检查发现45个input/select/textarea没有有效labels、aria-label或aria-labelledby；包括姓名、性别、电话、邮箱。依据 I05；CareerVaultPage.tsx FieldShell 使用独立label，FieldInput/FieldSelect未绑定id/htmlFor。未进行真实读屏用户研究，因此结论为程序化标签缺失，不声称已测所有读屏软件。

补测正向结果：I01 同标签刷新恢复已保存稿；I06 375px经历库未出现整页横向溢出。正向结果也保留，不把全部交互都说成失败。

## 4 体验建议与未确认风险

以下不是已复现功能故障，需任务观察或专项测量后决定优先级。

- 手机首屏大量区域用于品牌、场景和历史入口，实际任务位置较低。建议收紧演示说明，把当前步骤和主操作提前；通过 NF-04 比较找到任务的时间，不能只按个人喜好判定。
- 用户页面显示内部服务名、英文mock通知、算法编号，增加理解负担。技术详情宜放“诊断信息”，正常路径以中文任务反馈为主。
- 日期/地区选择可能自动补默认值。要测清空年后先选月、切省后市值；不能让默认值被误认为用户确认的生日或居住地。
- 卡片悬浮详情在触屏/键盘是否完整、复制权限拒绝是否有反馈、路由回退是否保留编辑、长说明是否遮挡操作，分别用 UI-05/CF-02/IX-06～08 验证。
- 当前未测真实用户任务完成率，不能宣布“体验显著提升”。

## 5 页面验收时的五个统一问题

1. 用户是否知道当前步骤、数据来源和是否保存？
2. 点击主按钮后，提示、实际数据和下一页是否一致？
3. 改输入、返回、刷新、取消、失败时，哪些内容保留，哪些结论失效？
4. 无鼠标、窄屏、长中文、失败状态下能否完成相同任务？
5. 结果能否通过日志/版本/来源解释，而非只看绿色提示？

所有交互修复都保留同输入、同视口的修复前后截图，并重跑数据/核验断言。单纯视觉变化不构成业务问题关闭证据。
