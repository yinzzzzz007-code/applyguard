# D-2 课程要求审阅（学者视角）

角色：学者（研究者视角，不冒充真实学者）。

审阅范围：仅审阅用户指定的三份课程 PDF 提取文本，不据此宣称软件已实现或已通过测试。项目基线由主审计指定为 D-2 `816a246`；本文件未独立核验代码。页码均为 PDF 文件的 **1-based 页码**。

## 1. 核心结论

老师要求的是**能运行的完整系统，以及别人能够检查、复现的工程证据**。界面改善有助于“可用界面”和真实任务演示，但不能替代需求、失败处理、测试结果、AI 评价和使用记录。

- **英语要求针对汇报和最终技术报告，未发现产品 UI 必须英文的要求。** 中文演示界面、中文种子数据与英文口头答辩/英文最终报告可以并存。
- **测试必须同时核对返回结果和持久化状态。** 只出现提示、只展示成功路径、只给截图或覆盖率，不能充分证明操作正确、失败无残留、历史数据不串用。
- **AI 评价允许评价 AI 行为或 AI 辅助工作流。** 不能把“用了 AI”“测试是 AI 写的”当成评价；必须保存输入、输出、人工修改、检查、结果及剩余风险。

### 3.2 不应被升级为硬交付的内容

- **用户研究：** 材料要求明确目标用户、具体需求、相关工作与未明规则（Kickoff p5；需求讲义 p6–8），未规定必须多少次访谈、问卷样本数、统计显著性或特定用户研究报告模板。访谈、任务观察、可用性测试属于可采用的方法；没有实施记录时应写“计划”，不能写“已验证”。
- **课堂练习：** 需求讲义 p58 明确是 15 分钟个人练习，产物为领域模型、SSD、短契约。p52 要求两张成功/拒绝 SSD 是该 AI 改写练习的输出；不能无条件宣布为期末独立文件数量要求。
- **图书馆/会议室数据：** 需求讲义 p8、p12、p47 的 14 天和日期，p56 的 09:00–17:00 都是案例约定。p62 强调单一“空闲”检查仍可能漏掉“最早”和“时长不变”，应迁移验证原则，不能套用业务数据。
- **真实外部动作：** Kickoff p34、p38 要求真实地图/日历或真实执行通道，是旅行、会议两个特定选题的基线。不得未经确认把它升级为 D-2 必须真投递简历的要求。D-2 采用模拟 ATS 时，应明确模拟边界，并证明准备填写资料这一实际任务有用。
- **量化标准：** 未发现强制测试用例数、代码覆盖率阈值、时延/并发数、AI 准确率阈值、报告页数。测试计划可提出团队建议值，但必须标注“待团队确认”，不得归因老师。
- **界面规范：** 未发现必须腾讯风格、采用某个设计系统、产品中文/英文的课程规定。腾讯校招风格、awesome-design-md、中文化等来自用户本次需求，应纳入项目验收而非教师原文。

## 4. 机制图与三条关键判断

**机制图：** 真实用户任务 → 明确边界/术语/规则 → 成功与失败契约 → 可重复检查 → 可检视结果与局限 → 人工验收 → 可答辩系统。

| 判断 | 证据级别 | 来源与适用范围 |
|---|---|---|
| “演示能跑通”不足以证明已满足作业 | 第一方课程要求；不是经验性科研结论 | Kickoff p8–10、p40；Lecture01 p31、p34、p55。直接适用于本课程最终验收，但不据此臆测评分权重 |
| 测试应同时检查用户结果和状态变化/不变 | 课程方法与教学案例 | 需求讲义 p15、p41、p43–50、p61–62。D-2 可迁移到保存、替换源、匹配、审查；具体不变式需从 D-2 业务定义，不能照抄借书规则 |
| 中文 UI 与英文汇报/报告不冲突 | 第一方显式语言要求及材料范围内未发现 UI 语言约束 | Kickoff p7–10。结论限于本次三份材料；未读到的后续课堂通知可能另有规定 |

**主要反例/替代解释：** 演示数据刚好匹配可掩盖识别与证据串用错误；高代码覆盖率可能来自未验证业务断言的测试；“保存成功”提示不等于后端落盘；来源链接存在不等于支持该陈述；人工编辑能够纠错不等于系统已正确识别。

**易误解术语：证据。** 工程证据是能支持具体主张、可定位/检视/复现的输入、步骤、实际结果与判定。UI 上名为“证据”的条目只是待验证对象，不天然构成匹配正确性的证明。

## 5. 最小先修、诊断题与证据缺口

最小先修：系统边界、功能/业务规则/质量/约束、领域身份与历史状态、成功/拒绝后置条件、不变式、预期与实际结果、需求追踪。

诊断题：用户上传新 PDF 后解析失败，旧经历是否还存在？用户看到什么？新草稿、旧简历、证据来源、匹配结果分别是否改变？请给一条契约和一个同时检查返回信息与后端状态的测试。如果只能回答“弹出错误”而说不清状态保证，尚未把课程方法应用到系统。

给实践者的问题：**“覆盖率”究竟是被 JD 条目覆盖的比例、具有合格证据的比例，还是自动化测试代码覆盖率？每个分母、阈值与例外由谁确认？** 此问题会直接改变 UI 展示、匹配验收和报告结论。

未决证据缺口：

1. 两张课程日历/里程碑图已由主审计视觉核查，未见提案/期末截止日期文字；最终日期仍需后续正式通知。
2. 本材料未给最终详细评分 rubric、提案页数、报告篇幅、量化验收门槛及后续通知。
3. D-2 的真实用户研究、业务阈值、测试执行结果和 AI 评价结果，必须由项目材料与实际执行提供，本课程审阅不代替验证。
4. 英文最终报告与本次中文问题/测试计划属于不同交付用途；本次中文稿可以供团队实施，正式提交时再形成英文最终报告。
