## 4 已复现问题

### D2-01 P0 无证据陈述进入可复制稿

- 前置：正常离线工作流已返回，存在可继续的种子陈述。
- 步骤：简历审查手动添加“我独立负责千万用户推荐系统，获得全国竞赛一等奖。”→ 陈述核验点“确认保留原文”→ 网申页确认提示 → 人工确认。
- 实际：页面标“支持度 0%、无证据编号”，仍可保留；全文稿含该句且“一键复制全部”启用。后端独立核验该未知 claim ID 返回 BLOCKED。
- 原因：`ResumeReviewPage.tsx:109` 自行构造 NEEDS_REVIEW；`:152` 新句 evidence_ids 为空；`copyRules.ts:19` 将人工 confirm 作为可复制条件；`DemoContext.tsx:93` patch 不重算后端风险。
- 预期：新增句先进入后端当前简历版本，完成来源验证；无证据不能靠确认成为可用证据。编辑/新增使旧风险、字段与确认失效。
- 证据：browser-run-03 B04/B05、ui-unsafe-copy.png、api-audit-results.json；用例 CL-02、CL-03、CF-03。

### D2-06 P1 基准与中文种子失配 旧报告不能代表当前版本

- 步骤：当前目录运行 `python -m eval.c_benchmark`，与 `eval/results/c-offline-audit.json` 对照。
- 实际：4 个 expected VERIFIED 和 8 个 expected NEEDS_REVIEW 全部 BLOCKED；28 个负例也 BLOCKED。当前准确率 28/40=70%，误阻断率 12/12=100%，正确接受 0/4，接受精度分母为 0 因而 null。
- 原因：`eval/c_cases.json` 保留英文陈述；中文化后的 `data/career-vault.seed.json` 与基准措辞不再一致，`claim_validator.py:155` 检查新增词。旧存档为准确率 100%、误阻断 0。
- 反证：4 条中文种子原文直接核验仍为 VERIFIED。因此首先是基准迁移/版本留档失配，不能据此说中文主流程全部不可用。
- 预期：冻结旧集留作历史；建立中文及中英对应金标，人工复核语义后另版本评价，不为追求高分直接改 expected 标签。
- 证据：benchmark.log、api-audit-results.json；用例 AI-01、AI-02、LG-04。
