# ApplyGuard D-2 完整测试计划

## 1 目标和适用版本

基线 `816a246`；本计划用于在此基础上完成用户列出的产品改进后的验证。当前问题和实际结果见 02 文档，详细用例见 04 文档。除 02 文档列明的实测外，计划内容均为待执行，尤其不将尚未开发的 PDF、后端草稿、竞赛结构化能力写成已通过。

验收目标：求职者能从可选 PDF 或空白经历库开始，保存可恢复的中文简历，针对岗位获得可解释的匹配，修改后重新核验，在模拟网申与人工确认页获得同一版本、允许复制的填写稿。错误输入、低证据、保存失败不能变成假成功；全程不真实投递。

本计划的指标、样本量、优先级是团队建议。课程明确要求见 01 文档，未给出的数字不归因教师。

## 2 范围与边界

范围包含：前端表单与流程、PDF 解析与人工修正、竞赛数据、API 与契约、证据图/匹配/选择/核验/风险、模拟 ATS、复制与本地历史、磁盘持久化、中文显示、可访问性、恢复、安全、性能、AI 评价、文档与交付。

本轮产品边界：单机本地草稿；模拟招聘网站；不自动投递；不推断敏感字段；技术专有名与内部 ID 无须翻译。真实招聘网站登录、验证码、真实账号、付款和真实投递不在测试范围。多用户服务与公网部署若后续加入，需另做身份鉴权、数据隔离与部署测试。

扫描 PDF/OCR 的支持策略须在实现说明中明示：支持则评价 OCR 和竞赛字段；暂不支持则给清楚提示与手填入口，不能返回空白“成功”。

## 3 三条端到端用户故事

1. **直接填写**：新用户跳过 PDF，填写基本资料、教育、项目、竞赛，保存，重启恢复，用中文 JD 匹配，处理证据与陈述，得到可复制稿。
2. **导入并修正**：用户上传中文 PDF，核对提取字段并改正奖项/日期，确认替换旧稿，再次匹配与核验。新来源可追溯，旧种子不参与当前结论。
3. **异常恢复**：用户遇到损坏 PDF、保存失败、模型超时或无证据陈述，得到准确状态，已有数据完整，可重试/手填/拒绝，并有可回查日志。

每条均需成功、拒绝和恢复路径，不能只录第一条的正常过程。

## 4 建议先固定的领域与操作契约

以下字段/接口语义是验收建议，并非声称当前已有 API。实际端点由实现确定后登记 `contracts/` 和接口文档。

核心实体：Candidate、ResumeDraft/ResumeVersion、Education、Experience、Award/Competition、Claim、Evidence、JDVersion、Match、Application、Verification、Audit。每个来源至少能定位来源文件/条目和所属简历版本；PDF 来源可进一步定位页码/原文片段。

| 操作 | 前置 | 成功后置条件 | 失败或取消后置条件 |
|---|---|---|---|
| 导入并替换 | 文件通过基础检查；用户知道将替换当前稿 | 提取预览经确认后，一次性建立新版本；活动旧经历/旧证据/旧核验/旧字段确认退出；页面提示替换结果 | 不提前删除旧稿；部分提取不伪装完整成功；取消无变更 |
| 保存草稿 | 字段可解析，草稿归属正确 | 后端写入 data/local 并可读回；响应带版本/保存时间；界面才绿底 | 旧成功版本不损坏；编辑内容仍在；dirty 保持；显示失败与重试 |
| 修改 JD/经历/陈述 | 当前有活动版本 | 派生匹配、核验、风险、复制授权显式过期；重新运算后绑定新版本 | 不能拿旧结论覆盖新内容 |
| 添加陈述 | 可手填，但最初没有真实性保证 | 新 ID、有版本、必要来源关联；后端验证产生结果 | 无证据或伪造结果为阻断/不可复制；不能仅靠前端确认放行 |
| 人工确认 | 当前版本及所有必需检查有效 | 确认绑定版本；稿件只含允许内容；历史是模拟摘要 | 阻断、待重核验、过期的内容不进入稿件；敏感缺项由本人填写 |

六个不变式：

- I1：当前候选人、简历版本、JD 版本、证据和结论相互一致。
- I2：失败保存/失败导入不破坏最后一次有效数据。
- I3：无证据、冲突或 BLOCKED 内容不能因点击确认成为可复制内容。
- I4：任何影响事实的编辑都会撤销旧核验、旧字段确认与旧复制授权。
- I5：一次用户动作不产生重复经历、重复奖项、重复历史或交叉覆盖。
- I6：模拟全程只产生本地结果，私人草稿、上传文件和敏感日志不进入 Git。

“PDF 后清空原简历”按**成功确认替换时清空活动旧稿**验收；若解析失败就先删除旧稿，会造成不必要的数据丢失。此解释写进界面提示和契约，供团队实施。

## 5 测试层次与技术

| 层次 | 重点 | 方法与判据 |
|---|---|---|
| 单元 | 日期/地区、竞赛字段、中文词归一、强弱阈值、copyRules、存储编解码 | 等价类、边界值、决策表、参数化反例；调用生产函数 |
| 契约 | 九份已有 schema 与新版本/PDF/奖项/草稿契约 | 正反例、缺字段、错类型、重复 ID、跨候选人、非有限数；错误码和状态都断言 |

| 组件 | 表单 dirty/saving/saved/error、弹层、禁用条件 | 实际组件事件；禁止通过复制一份业务算法来自证正确 |

| AI/规则评价 | 解析、匹配、陈述真实性、模型回退 | 冻结金标与配置，混淆矩阵、错误分层，模型与规则分组报告 |
| 可用性 | 用户理解强弱/待核验/模拟、完成任务、找来源 | 任务观察、计时、错误和修改记录、简短访谈；不冒充统计代表性 |
| 非功能 | 性能、并发、恢复、隐私、可访问性 | 小规模受控压力、强制中断、键盘和屏幕宽度矩阵 |
| 交付 | 干净克隆、运行步骤、证据包与课程材料 | 新环境复现；报告数字必须可回算 |

状态转移重点：`未保存→保存中→已保存/保存失败`、`待提取→提取中→待复核/失败→已替换`、`草稿→核验中→可用/待审/阻断→修改后过期`。每条边都检查 UI、API、数据；不只检查按钮点击成功。

推荐先做 12 份 PDF（文本 4、复杂排版 3、扫描 2、损坏/加密/超限各 1），10–20 份 JD 与不少于 40 条陈述作为首轮工程集；这些是启动建议，不是充分样本量。调规则用开发集，最终报告用冻结保留集；相同简历改名/改排版不应跨集合泄漏。

用户研究建议 5–8 名目标用户进行形成性任务测试，每人做直接填写、PDF 修正、解释强弱与拒绝错误三类任务。报告人数、招募、经验、指导程度、失败和完成率分母；小样本只定位问题，不宣称普遍提升。沿用 `docs/user-study/` 和 `docs/usability-study/D-task-study.md` 的同意、任务与记录模板，未实施不填假结果。

## 8 边界与组合策略

- JD 字符：0、19、20、20000、20001；纯空格、emoji、换行、HTML文本、未识别领域；区分前端 JS 长度和后端字符计数口径。
- API body：缺/负/非法 Content-Length、0、上限 262144 bytes 及上限+1；按当前服务约束验证，不能无限发送等待占用服务器。
- 日期：2月28/29日、闰年/非闰年、月末、结束早于开始、未来出生日期；是否允许“至今”明确。
- 分数：阈值前/等于/后；0/1、空集合、重复要求、多个来源、冲突高分、弱相关高词频。
- 手动内容：空、纯空白、长文、重复点击、数量和总字数临界值；不得绕过自动选择的风险边界。
- PDF 文件大小/页数以最终配置 L/P 为准：0、L−1/L/L+1、P−1/P/P+1，计划不假定当前已有 10MB 等上限。
- 存储/版本与数据源做重点组合：保存失败×页面切换；替换×慢匹配；手动添加×旧确认；竞赛删除×证据引用；PDF跳过×空经历。

一般组合用成对覆盖控制成本；I1–I6 的高风险组合完整覆盖，不以成对策略删掉已知失败链。

## 9 指标 口径与建议门槛

| 指标 | 计算与分母 | 建议验收方式 |
|---|---|---|
| 功能需求覆盖 | 有可执行验收用例的需求数 / 本轮需求总数 | 100%，但这不代表用例都执行 |
| 通过率 | PASS / (PASS+FAIL) | 同时列 ERROR/BLOCKED/NOT_RUN，防止隐藏未执行 |
| 强证据覆盖 | 有至少一条当前、无冲突、可核验直接证据的唯一要求数 / 唯一要求总数 | 硬条件与加分项分开；0要求显示“不适用” |
| 相关匹配分数 | 当前算法相关性得分 | 标“相关度”，不得叫成功率/录用概率；不当作上述覆盖率 |
| JD precision/recall | 正确要求/(提取要求)；正确要求/(金标要求) | 报原文、类别、否定分别误差；首轮建议≥90%，由团队冻结 |
| 可接受陈述精度 | 真有证据且被接受 / 所有被接受 | 硬负例泄漏必须0；分母0显示N/A，不显示100% |
| 正确接受率 | 支持且被接受 / 所有应可接受 | 防“全部阻断”；建议≥95%，保留绝对数 |
| 误阻断率 | 应非阻断却被阻断 / 所有应非阻断 | 建议≤5%；分VERIFIED/NEEDS_REVIEW分别报告 |
| 字段提取准确率 | 正确已填字段 / 预期非空字段；另报空值误填 | 姓名/联系方式/奖项级别等高影响错误不能自动确认；建议≥95%仅适用于已声明支持的文本PDF |
| 操作成功率 | 独立完成且结果正确任务 / 所有开始任务 | 同时报中位时间、修正次数、求助次数；不得删失败者 |
| 延迟 | 同进程记录p50/p95/最大值与样本数 | 本机离线工作流建议p95≤2s，保存≤1s，普通文本PDF≤5s；记录硬件，首次与热启动分开 |

上述质量百分比是团队建议，不能在未建金标前声称达到。课程不要求特定百分比。安全与数据不变式按逐例“零违反”门禁，不用整体平均分掩盖失败。

可访问性建议目标：普通文字对比度至少4.5:1、大字3:1，参考 [W3C WCAG 2.2 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)；键盘弹层的焦点、Tab约束和Escape参考 [W3C APG 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。关键状态除颜色外有文字，触控目标足够。对比度可用计算工具测量，最终按实际产品需求确认；这是团队建议的验收参照，不是教师指定标准。

### 每次改动的最小回归集合

- UI 文案/token：构建、lint、UI-01/03/04/06、受影响页面截图。
- seed/中文词典：契约、JD/MT/EV、AI-01/02/03、E2E-01；同步数据文件与预录版本。
- 保存/PDF/奖项：SV/PF/AW、版本隔离、E2E-02/03；重启读回。
- 陈述/门禁/ATS/复制：全部 CL/AT/CF、无证据和篡改负例、E2E-04。
- 部署/依赖：EN全组、构建、静态资源和深链接、E2E-01。

核心修改提交前跑所影响集合；合并前完整离线自动集；候选发布版做浏览器与金标评估。真实模型运行单独安排，固定提供者/实际模型ID/配置/预算，不能在普通离线回归中暗中联网。

## 11 进入 暂停 恢复与退出

进入：能启动或明确标记环境阻塞；测试虚构数据/金标就绪；日志目录可写；版本已记录；待测功能已实现且契约可判定。

暂停该用例：可能接触真实提交或真实个人数据；日志写入失败；服务/数据目录指向错误环境；关键版本不可识别。先修环境并建新 run，不擦掉已执行记录。产品缺陷本身记 FAIL，不把所有失败归咎环境。

发布建议门禁：

1. 无开放 P0；核心任务 P1 为0，其他已知限制由团队明确签署范围并在演示/报告披露。
2. I1–I6 全部相关案例通过，成功与失败恢复均有证据。
3. 后端、构建、lint（警告有处置）、真实组件/浏览器回归通过；不把逻辑副本测试当E2E。
4. 当前代码、种子、测试集、评估和预录版本一致；不得使用失配旧指标。
5. 已承诺功能均执行；NOT_RUN/BLOCKED 不计通过；真实模型未测则仅声明离线能力。
6. SHA256清单校验通过，关键日志/截图/请求/输入均齐全；另一名成员能复现至少正常、异常、护栏三条路径。
7. 私人草稿不被跟踪；英文正式报告和演示使用实际数据且说明模拟边界。
