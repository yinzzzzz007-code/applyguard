# 详细用例与需求追踪

## 1 执行约定

本文件是验收规格，不是已完成测试表。初始状态为 NOT_RUN；功能未实现时记录 BLOCKED 并引用缺口，不能填 PASS。部分步骤已有本轮实测，引用 02 文档及具体 run/case；只有本行所有断言实际执行后才更新状态。

每条用例都建立独立 case 记录：版本、前置、实际输入、步骤、预期、实际、状态、执行者、时间、缺陷ID、证据相对路径。步骤按顺序执行；结束后恢复隔离测试数据，不改真实简历。

证据代号：**E1** 输入文件/请求及SHA256；**E2** 运行stdout/stderr、退出码/HTTP状态；**E3** 响应与保存前后数据快照；**E4** 截图/DOM/浏览器trace/console；**E5** 人工金标与逐项差异；**E6** 版本/环境/清单。每条至少E6+case.json，表内另列业务证据；敏感数据用虚构或脱敏件。

共用数据：A为“测试用户甲”，B为“测试用户乙”；新手动反例为“我独立负责千万用户推荐系统，获得全国竞赛一等奖。”；JD-A为客户端默认后端岗位，JD-B为财务岗位。所有姓名、联系信息、奖项均虚构。
