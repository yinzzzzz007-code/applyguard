# 测试日志与留档规范

## 1 硬规则

**测试必须留档。没有日志/实际结果/证据路径的用例不能标 PASS；失败、环境错误、脚本错误和复测都要保存。** 本规则来自用户本次明确要求，并落实课程“可检查、可重复”的验证要求。

- 一次执行一个新 run_id，不覆盖既有目录；同版复测也新建。
- 先记录版本、环境、输入与预期，再运行，再填实际和判定。
- 同时保存 stdout/stderr、退出码、时间、用例ID、环境和输入版本。
- 自动命令退出0不等于业务通过：基准脚本退出0仍可能40条全阻断，必须审指标。
- 产品失败记 FAIL；脚本或环境不能完成记 ERROR；依赖功能未实现记 BLOCKED；未跑记 NOT_RUN。
- 修复后保留“原失败 → 修复提交 → 新运行 → 复核”链，不能用新日志盖旧日志。
- 只保留真实执行的结果。截图只证明当时画面；核对持久化需文件/读回证据；模型评价需输入输出和模式。

## 2 目录与命名

推荐完整原始材料存现有忽略目录 `output/test-runs/`，供本地长期保存；可公开的虚构/脱敏证据复制到 `docs/testing-D2/evidence/` 并由团队决定提交。业务草稿在 `data/local/`，与测试证据分离。当前 `.gitignore` 尚未排除 data/local，这是待修问题，不能因本文写了目录就认为已修。

```text
output/test-runs/
  20261006TxxxxxxZ-816a246-随机后缀/
    run.json                  # SHA、环境、开始结束、执行者、模式
    commands.json             # 每条命令、工作目录、退出码、日志名
    git-status.txt            # 本轮工作树状态
    tracked-diff.patch        # 跟踪文件差异；本地保留，公开前检查
    hashes-input.json         # 锁文件、种子、测试集哈希
    logs/
      backend-unittest.log
      frontend-build.log
      frontend-lint.log
      frontend-smoke.log
      offline-benchmark.log
    cases/CL-03.json           # 逐用例实际结果
    inputs/                   # 虚构输入原件或受控引用
    responses/                # 请求/响应与trace_id，去秘密
    screenshots/              # case-step-state.png
    traces/                   # Playwright trace，可含正文须控访问
    data-snapshots/            # 保存/替换前后，便于验证不变式
    issues/                   # 缺陷复现与修复记录
    summary.md                # 结果汇总、限制、风险、建议
    manifest.sha256.json      # 全部归档文件的相对路径、大小、SHA256
```

真实简历或含个人信息的 trace 不复制到公开 evidence。不能通过把 data/local 加入 Git 来实现“测试留档”。

## 3 每轮必须记录什么

| 类别 | 必填信息 | 禁止做法 |
|---|---|---|
| 版本 | 完整SHA、分支、dirty状态、必要diff、依赖锁与数据集hash | 只写“最新版” |
| 环境 | OS、区域/编码、Python/Node/npm/浏览器、视口、入口、端口、时区 | 记录全部环境变量泄露密钥 |
| 输入 | 虚构候选人、简历/JD版本、文件hash、实际请求 | 仅写“普通简历” |
| 操作 | 测试ID、顺序、命令/脚本版本、故障注入方式 | 事后凭记忆补造步骤 |
| 输出 | 原始返回、退出码、trace_id、文件/状态变化、console | 只截成功提示，不检查磁盘 |
| 判定 | 预期/实际、PASS/FAIL/ERROR/BLOCKED/NOT_RUN、issue ID | 空证据PASS，或隐藏失败样本 |
| 复测 | 原run、修复SHA、新run、复核者、剩余限制 | 仅将旧FAIL改为PASS |
| AI | 实际provider/model、参数、prompt版本、规则/模型/回退、重试、tokens/费用如可用 | 把mock、预录、规则算模型能力 |
| 隐私 | 数据为虚构/脱敏方式、受控原件位置、公开审核人 | 将真实证件号、密钥、完整简历推送 |

机器时间不一致时保留原始来源和时区；同一次计时用单调时钟。不可把两个不同进程的时间差当响应耗时。

## 4 自动采集脚本

仓库附带 [scripts/Collect-TestEvidence.ps1](scripts/Collect-TestEvidence.ps1)，自动采集当前已有的后端测试、前端构建/lint/smoke、离线基准，保存命令与退出码，并生成SHA256清单。它**不安装依赖、不调用付费模型、不上传、不push，也不改业务代码**。运行前安装 README 所需依赖。

从项目根目录执行：

```powershell
pwsh -File .\docs\testing-D2\scripts\Collect-TestEvidence.ps1 -Executor "成员姓名"
```

Windows PowerShell 环境可用 `powershell -File`。若系统策略阻止脚本，按课程/团队环境规则解决，不要求永久降低系统策略。Python解释器可显式指定：

```powershell
pwsh -File .\docs\testing-D2\scripts\Collect-TestEvidence.ps1 -Executor "成员姓名" -Python "D:\jianglingtian\miniconda3\python.exe"
```

运行结束打印目录；任一命令FAIL/ERROR时采集器返回1。检查 `commands.json`；基准状态为 `REVIEW_REQUIRED`，因为退出0不能判断指标可接受。每轮同时保存采集脚本快照。已实际验证正常采集，以及“解释器不存在”的ERROR仍会留下日志和清单。将每条case记录及截图/trace加到同目录后，重新生成清单：

```powershell
pwsh -File .\docs\testing-D2\scripts\Collect-TestEvidence.ps1 -FinalizeOnly -RunDirectory "本次运行绝对目录"
```

FinalizeOnly 会增加修订清单及更新当前清单，不覆盖原始测试日志；只在所有资料齐全后封存。封存后修改证据应创建新运行或新包，不悄改旧文件。清单只保障完整性，不等于第三方时间戳或防伪签名。

## 5 浏览器和API如何留证

浏览器：固定viewport/locale/timezone；独立上下文；每个关键操作前后截图；收集console/pageerror和本地API请求；启用trace；记录browser.version。断言读取真实DOM/响应，不重写生产算法。复制测试用隔离文本框，不去真实招聘站点粘贴。

API：保存method/path、脱敏请求、响应status/body、trace_id、耗时、输入hash。持久化案例留保存前/后文件列表和hash，重启后再GET/打开页面核对。失败请求返回422本身不是FAIL，要对照预期拒绝及状态未变。

故障注入：写清“模拟QuotaExceededError”“断开本机后端”“fake模型超时”，不能描述成真实磁盘或真实提供者事故。仅在隔离测试目录注入权限/坏文件/中断。

本轮原始脚本 `api-audit.py`、`browser-audit.cjs`、`interaction-audit.cjs` 随证据保留。其浏览器运行器路径是本机配置，其他成员复现时应替换为本机已安装Playwright/Chrome位置；生产项目没有新增Playwright依赖。

## 6 缺陷与复测格式

```text
缺陷ID：D2-01
优先级：P0
基线：完整SHA
关联需求/用例：R05 R07 R16 / CL-03
前置：正常离线工作流，有合格种子句
输入：inputs/manual-claim.json，附SHA256
步骤：加入无证据句→确认保留→ATS确认→检查全文稿
预期：不能进入可复制稿
实际：填写稿含该句且复制按钮可用
证据：run目录 + B04/B05、截图、trace、后端独立判定
修复提交：未填写
复测run：未执行
复核者：未填写
关闭条件：原复现和相邻风险回归均通过
```

重新跑通过后新增复测记录，原“实际”不改变。无法复现时写本次输入/环境差异，不能直接关闭。

## 7 汇总表和门禁

每轮总结至少：计划数、实际执行数、PASS、FAIL、ERROR、BLOCKED、NOT_RUN、P0/P1开放数、证据缺失数、主要失败链、未覆盖范围、能否发布。用例覆盖率、执行率、通过率分开计算。

课程最终报告引用稳定相对路径及必要截图，并注明该指标来自哪个 run/SHA/数据集。`eval/results` 旧指标与当前运行不一致时必须保留两版并解释；本轮已经发现这一情况。

封存检查：

1. 清单内文件全部存在、大小/hash一致；用例提到的证据路径均存在。
2. 修复与复测链接完整；未执行的项目没有被计入PASS。
3. 原始失败与脚本ERROR仍保留。
4. 公开版无真实个人信息/凭证，私有原件与公开脱敏件通过ID对应。
5. 另一名成员从命令与输入能重复核心结果。

## 8 保存 备份与责任

建议原始证据保留至课程验收完成后至少90天，或遵从团队/课程后续要求；这不是教师已规定的保留期。一个成员负责证据目录，另一成员负责复核清单。日志丢失或文件损坏必须复测，不伪造补写。

本地完整包至少另备份一份到团队允许的受控位置；只有经检查的虚构/脱敏证据才随Git提交。当前请求未要求上传，本次只落本地文件。任何真实个人数据的保存期限按当事人同意和项目规则制定。
