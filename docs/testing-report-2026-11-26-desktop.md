# Windows 实际 EXE 验收 · 2026-11-26

本轮使用 E 盘上的冻结 EXE 和真实 ChatAnywhere Gemini 请求，数据与原个人工作区隔离。所有演示材料明确标注为模拟，不能视为真实项目证明；冲突由实际核验发现，未预先写入判定结果。

## 真实故障及修复

| 故障 | 根因与修复 | 验证 |
|---|---|---|
| E 盘 SAG 索引失败 | E 是 exFAT，不支持所需链接操作。运行文件与索引自动选择本机可写 NTFS，原材料和资料留在 E。 | 冻结 EXE 完成 LanceDB 创建、查询和完整 SAG 引擎初始化。 |
| 模块能导入，但引擎不能运行 | 冻结包缺少运行时动态加载的 aiosqlite。显式收集依赖。 | `--check-storage` 检查引擎初始化，不再只检查 import。 |
| 成功检索却显示核验失败 | Windows GBK 流无法输出 SAG 日志中的 ✓，错误日志又再次触发编码异常。 | 标准输出、错误流使用 UTF-8；测试覆盖 GBK 和无控制台 GUI。 |
| 多个演示同时启动失败 | 首次准备共享缓存时发生抢写。 | 内嵌文件校验、缓存互斥；三个独立桌面后端均返回健康状态。 |
| 已有明确反证却降为待复核 | 用模型改述的事实检查原文摘录；又依赖 DRAFT/SOURCE 之间的连接词。 | 先绑定正文位置，再分别核对两端摘录。原文不存在、引文伪造及跨项目材料仍不获支持。 |
| 采用后按钮说没有改写 | 已采用状态沿用未生成建议的禁用说明。 | 明确显示“已采用 · 正文已更新”。 |
| 已知冲突的严格导出再次超时 | 严格导出无条件重跑模型，第三份实测返回 503。 | 只对服务端保存的同候选人、同正文、同材料快照、有引用的冲突提前拒绝；不复用历史通过状态，不影响主动重新核验。 |
| 禁用按钮不解释原因 | 12 处原生按钮缺少直接说明。 | 改用共享动作按钮；材料读取失败可在页内重试。 |

## 本机记录与范围

全量后端回归：**524 项通过，0 跳过**（最终日志 `output/full-regression-final-3.log`）。前端：**97 项通过**，生产构建通过。按钮静态检查覆盖 277 个定义、143 处条件禁用，未发现空处理函数及缺少直接禁用说明的原生按钮。静态检查不等于对所有运行状态逐一手动点击。

补测原跳过项：普通命令默认尝试 PaddleOCR，而桌面使用 RapidOCR。切换为实际桌面配置后，图片型 Word OCR 及相关 70 项用例均通过；最终全量回归没有跳过。

五条正文压力测试返回 5 条实际改写；本轮耗时约 **593 秒**。等待时切到经历库，再返回简历审查，结果和历史对照能够恢复。实际点击采用后，正文、历史和最终稿使用新文字。该时长来自一次真实请求，不是性能上界；录制宜使用真实历史回放或剪掉等待，不能把回放说成即时生成。

三份文件为 `01_21885a249ba6d740fef636a86498cc8d.pdf`、`02_c552562e6214195b77ed63ffeb052580.pdf`、`03_58ab22aedcd661a5ece5bf3210bfc743.pdf`。均通过冻结 EXE 的本地 OCR 导入，识别出 4、1、3 个项目。01 识别出姓名；02 的姓名为占位文字，03 未提供可用姓名，程序留空。

完整验收将每份导入整个经历库，再人工选择一项相关项目作为本轮正文，依次执行润色、采用、检索材料、确认关联、核验、导出和面试。每次失败后的续测复用已经成功的润色回执，并明确记录；重新核验仍发送新模型请求。

详细私有记录位于本机仓库 `output/three-final-exe/01`、`02`、`03`，含逐项摘录与定位结果；五条压力测试位于 `output/exfat-exe-live`。原始资料与密钥不上传 GitHub。真实 GitHub 私库授权必须由用户在官方页面完成，未授权时不宣称已测试私库读取。
