## 1. 本轮已完成（可直接演示）

### 1.1 原「网申模拟」→「申请内容检查」`/ats`

| 项 | 现状 |
| --- | --- |
| 标题 / 副标题 | 「申请内容检查」；说明本页用演示表单 |
| 页面顺序 | 当前状态和下一步 → 候选人摘要 → 需要本人填写 → 其他检查结果 |
| 主按钮 | 有缺依据经历时：**去核对经历**；否则在确认完成后：**进入确认页** |
| 次按钮 | **查看确认页**（`/confirm?view=1`），不强制勾选「我理解」 |
| 候选人摘要 | 按 `source_claim_ids` 逐条展示状态与原因，可链到陈述锚点；完整拟填值默认折叠 |
| 工作许可 | 显示「待本人填写」；勾选不算已填写 |
| 风险提示 | 离线提醒合并；岗位要求汇总为「现有资料未见对应覆盖」，不提「缺支持材料」 |
| 关键逻辑 | `frontend/src/atsCheckView.ts` |

关键文件：`AtsSimulatorPage.tsx`、`atsCheckView.ts`、`ClaimVerificationPage.tsx`（陈述 `id` + hash 滚动）、`navigation.ts` / `flow.ts`。

### 1.2 确认页 `/confirm`

- 阻断时只读查看不会解除阻断。
- **可复制**：阻断陈述红底标出；整页预览稿不再「全红」。
- 仅 `claim_verification.state === 'BLOCKED'` 的句子标红；待复核 / 本地未重核不标红。
- 候选人摘要字段因含阻断陈述而不可作为「已通过」，但整段摘要不再整块红底。

关键文件：`HumanConfirmationPage.tsx`、`index.css`（`.copy-value-blocked`）。

### 1.3 原「申请记录」→「简历生成」`/history`

- 三种模板：中文学术技术 / 英文标准单栏 / 中文校招一页。
- 姓名左对齐页眉（不当居中大标题）。
- **编辑预览（可删除）**：可删整段、整条经历、单条要点；只影响本次导出，不改经历库。
- 复制 TXT / 下载 / 打印 PDF；打印时隐藏壳层与「恢复进度」提示、删除按钮。
- 底部仍保留本地申请模拟记录摘要。

经历库新增字段（生成简历用）：

- 基本信息：GitHub、LinkedIn、个人主页  
- 教育：GPA、学校所在地、相关课程  
- 实习/项目：地点、技术栈、链接  
- 技能区：语言能力、研究兴趣、论文/科研成果  

关键文件：`ApplicationHistoryPage.tsx`、`resume/generate.ts`、`resume-generate.css`、`formModel.ts`、`types.ts`、`CareerVaultPage.tsx`。

### 1.4 其它体验

- 顶部「已恢复上次申请进度」可点「知道了」关闭；文案标明是恢复进度而非新审核结果。
- 打印 CSS：隐藏 `.workspace-notice` 等，避免进 PDF。

## 2. 建议组员接着改（按优先级）

### P0 · 体验与正确性（建议先做）

1. **简历预览编辑是否写回经历库**  
   现在删除只改本地 draft。组员可加：「同步到经历库」开关，或明确文案/二次确认，避免用户以为永久删除了。

2. **简历模板与样例对齐**  
   当前三种模板是结构近似，不是像素级复刻用户提供的多份简历。可拆任务：  
   - 再加 1～2 个模板（如灰条英文、校徽中文）  
   - 或把现有模板 CSS 再贴近样例（日期右对齐、要点加粗指标等）

3. **预览内联改字**  
   现在主要是「删除」。若需要改一句话，只能回经历库。可做 contentEditable / 小输入框，仍只作用于 draft。

4. **申请内容检查 · 教育类要求展示**  
   「14 项未见覆盖」已按 `profile_checks` 写备注，但学历未填时仍可能和「专业已匹配」混在同一列表。可按类别分组：个人信息 / 技能经历 / 软性表述。

### P1 · 产品完整度

5. **工作许可真正填写入口**  
   仍无独立字段，只能「待本人填写 + 勾选理解」。可在经历库「网申补充」加一项，并在 ATS 页链过去。

6. **简历生成 ↔ 当前岗位**  
   预览可选用目标 JD，高亮「已覆盖 / 未覆盖」要求（只对照现有资料，不提材料），方便按岗裁剪 draft。

7. **导出格式**  
   目前 TXT + 打印 PDF。可评估：HTML 下载、简单 DOCX、或固定 A4 分页预览。

8. **导航与文案全局统一**  
   帮助页、引导文案、`onboarding.ts` 里可能仍写「网申模拟 / 申请记录」。全局搜旧名称改干净。

### P2 · 工程与测试

9. **前端单测补强**  
   - `atsCheckView` 的聚合文案、教育类 note  
   - `resume/generate` 的纯文本输出与删除后 draft  
   - 打印相关：至少用 DOM 断言编辑按钮带 `resume-edit-remove` 类（打印 CSS 已隐藏）

10. **旧草稿兼容**  
    `normalizeResumeForm` 已填新字段默认空串；建议组员用真实旧 session 点一遍经历库保存 / 简历生成，确认不报错。

11. **联动回归**  
    本次同步还包含证据工作区、岗位解析及本地草稿恢复的改动。验收时请覆盖一次从证据核对、岗位分析到简历生成的完整路径。

## 3. 已知限制（不要当成 bug 硬修）

- 演示 ATS 表单基本只有「候选人摘要 + 工作许可」；经历短标题依赖 claim id / 匹配结果，对不上就截断陈述。  
- 预录样例 `uncovered` 常为 0；「N 项未见覆盖」主要出现在真实离线分析草稿。  
- 「网申映射不一致」= 摘要引用了已阻断陈述后，一致性被标 `BLOCKED`，应回陈述核验处理，不是改映射表。  
- 简历生成不调用模型，不自动投递；阻断规则与复制安全规则（`copyRules.ts`）未放宽提交条件。

## 4. 本地怎么验

```bash
cd frontend
npm run build
npm run smoke
```

手工路径建议：

1. 阻断样例或本地草稿 → `/ats`：主按钮「去核对经历」、查看确认页无需勾选。  
2. `/confirm?view=1`：只有已阻断陈述红底；可复制预览。  
3. 经历库补 GitHub / GPA 等 → `/history`：选模板 → 编辑预览删除几段 → 打印 PDF 无顶部恢复提示、无删除按钮。
