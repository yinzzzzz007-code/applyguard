# 简历识别结果带入经历库

1. 首页点“选择简历”，选择 PDF 或拖入上传区，等待识别。
2. 识别成功后，同一个按钮变为“导入到经历库”。点击立即跳转，不保存后端草稿，也不要求先处理差异。
3. 经历库自动形成未保存的分类卡片；已有经历及未保存修改保留，相同条目不重复增加。识别建议在对应卡片内展示，默认沿用已有内容，可使用建议、作为新经历或保留原内容。
4. 点卡片“编辑”，修改后点“完成编辑”返回总览；取消会恢复本次编辑前的草稿。
5. 最后统一点“保存经历库”。移除条目也仅修改草稿，保存后才生效。

“查看本次识别原文”显示完整识别正文。解析响应新增兼容字段 `source_text`；旧响应只有 `preview` 时仍可导入。

识别结果通过同一标签页的 sessionStorage 交接，在进入经历库后合并，并暂存到 `applyguard.resume-edit.v1`。跳转和刷新不会主动提交后端保存；浏览器存储不可用时明确提示保留页面。保存仍使用现有版本检查和接口，保存不等于核验通过。

实现：`resume/importTransfer.ts` 负责交接、草稿合并和建议采用；`CareerVaultPage.tsx` 负责最终保存。既有合并规则检查可运行 `python scripts/verify_vault_flow.py`，加 `--build` 检查构建。本轮构建通过；首页已观察到“选择简历”入口和旧保存按钮移除。后续文件选择交互因浏览器工具中断未完成，不宣称完整点击流程通过，不扩大测试范围。
