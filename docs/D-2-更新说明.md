# D-2 更新说明：岗位解析与回退提示

## 背景

在岗位说明页点击“运行模型工作流”后，一段中文大模型评测实习 JD 显示“模型条目未通过岗位原文核对”，随后以规则结果继续；页面却可能将旧结果说成“这次点的是离线工作流”。旧规则还把中文岗位显示为“未知岗位”，并只提取少量要求。

模型输出必须能由岗位原文支持。一次模型解析未通过核对时，工作流会改用规则结果；“等待人工确认”表示后续流程已返回，不能理解为模型解析成功。

## 本版改动

1. **明确请求与实际执行方式。** 后端在 `component_modes.requested_parse_mode` 回传 `DYNAMIC` 或 `OFFLINE`。前端根据本次响应的请求方式和 JD Parser 步骤轨迹展示“模型解析”“模型失败后规则回退”或“离线规则解析”，避免页面重新进入后因临时状态丢失而误报。连续发起请求时，旧响应也不会覆盖新响应。
2. **安全处理模型改写。** 当模型给出的 `evidence_text` 是原文中的精确片段、术语也能在该片段中核对，但 `text` 使用了不完全相同的表述时，解析器改用原文片段作为要求文本，并将置信度上限设为 0.7，标记为 `MODEL_SPAN_REPAIRED`。虚构术语、虚构公司、否定条件和注入内容仍不能靠这一步通过核对。
3. **改善中文规则结果。** 识别中文实习生等岗位名称；增加 Benchmark、LLM Harness、Eval Workflow、Checkpoint、vLLM、预训练、多模态、评测框架等术语；识别毕业条件和实习时长；过滤职位标题、招聘引言和章节标题，并去除重复要求。用户提供的完整文本在本地离线复测得到 **21 条**，每条均保留原文片段。公开仓库的回归测试使用简化样例，不包含完整原文。
4. **统一页面提示。** 岗位说明页、来源标签和网申模拟页区分主动离线解析与模型路径转规则；原文核对失败的提示改为“模型条目未通过岗位原文核对”。

## 验证

- 后端：`python -m unittest discover -s tests`
- 前端：在 `frontend` 目录运行 `npm run build` 和 `npm run smoke`
- 回归样例：`tests/test_jd_chinese_offline.py` 使用简化中文岗位文本，覆盖岗位名称、要求与原文片段、离线模式标识，以及“可核对的模型改写被校正、虚构技能仍被拒绝”。

本次在 D-2 工作目录验证结果：后端 **79 项测试通过**，前端构建通过，冒烟测试通过。

手动复核时，重启后端并刷新前端，粘贴该 JD 后分别点击“运行模型工作流”和“运行离线工作流”。模型路径如转规则，应显示请求为“模型解析”和对应原因；主动离线运行应显示“离线规则解析”。原文没有公司名，所以“未知公司”仍是正确结果。

## 边界

本版通过本地模拟模型输出验证了改写校正逻辑，没有取得用户当次模型的原始 JSON，也没有重新向外部模型发送这段 JD。因此无法判定当次具体是哪一条输出触发核对失败，或保证外部模型重新运行一定成功。网申字段映射仍是固定模拟映射。

此分支从 D-1 创建，仅包含本说明所列的修复及回归用例；原工作目录中其他未提交改动未纳入 D-2。
